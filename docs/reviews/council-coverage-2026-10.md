## Findings that matter first

1. **Suburb URL collisions discard already-ingested coverage.** `Ipswich` and `Ipswich ` write to the same URL; the live page shows one project instead of the combined 65 and loses the canonical suburb's cross-references. Eleven suburb slug groups collide.
2. **Traffic schema mismatch loses real street/suburb fields.** Seven sampled TMR events have `road_summary.locality`, but ingestion reads `suburb`. Three IMS events have `road`, nested duration/impact and GeometryCollection coordinates, which the IMS normaliser drops.
3. **The blanket CC BY assertion has contrary source evidence.** The very Council copyright page cited by project documentation requires consent for reproduction beyond its stated exceptions. Other sources have their own terms; TMR's API dataset does have a specific CC BY 4.0 listing. Resolve provenance before expanding republication.
4. **Freshness context disappears away from the homepage.** Street, suburb and division road-impact tables omit the snapshot time already stored and displayed on the homepage.
5. **Older mentions exist but are hard to reach from a place page.** A deliberate 50-row cap has no continuation link; Raceview advertises 162 news mentions but exposes only the latest 50 in that section.

These are smaller and better evidenced than adding another large source system.

## Ranked implementation candidates (proposals only)

### 1. Canonicalise suburb join keys and prevent silent page overwrites

**Benefit:** restore residents' existing projects, meetings, news, consultations and safe DA pointers at the URL they already use. **Confidence: high. Effort: about 0.5–1 day.**

Evidence: [live Ipswich](https://ipswichfacts.au/suburb/ipswich/) has `Projects (1)` (Incinerator Theatre, `INF05370`), while [published projects](https://ipswichfacts.au/data/projects.json) have 64 rows with `suburb == "Ipswich"` and one with `"Ipswich "`. The official projects feed carries those variants too. Published suburb data has **101 strings, 89 distinct slugs, 11 collision groups** (Springfield Lakes has three variants). Blackstone similarly renders one whitespace-suffixed project instead of joining three canonical projects and its other coverage. The offline renderer reproduces the overwrite. These are data already stored, not absent Council records.

Scope: canonical comparison keys using trim/whitespace collapse and casefold, with Council's original label preserved as source data; apply consistently to graph membership and rendering. Keep current canonical suburb paths. Reject conflicting writes or dedupe identical canonical paths. No fuzzy spelling correction, slash/newline splitting, DA expansion or project URL migration. Relevant paths: `scrape/civic_projects.py:normalise_feature`, `build/build_site.py:slugify`, `build_graph`, `render_suburb`, `write_site`, published `data/suburbs.json`, `data/url_registry.json` (preserve project assignments).

Dependencies/constraints: no new source requests; candidate 3 resolves outstanding reuse claims. Do not alter proposal text or expose additional DA fields.

Acceptance:

- A fixture with `Ipswich`, `Ipswich ` and case/whitespace variants yields one suburb page and one sitemap URL, with all **65 sampled project IDs** represented once.
- Existing `Ipswich` consultation/news/meeting/DA references join that same canonical bucket; an empty variant cannot overwrite it.
- All 11 observed suburb collision groups are checked; project slugs are unchanged and unknown/multi-locality labels are preserved without invented assignments.
- A conflicting duplicate page path fails visibly; existing invariant/URL tests remain green.

### 2. Repair the traffic adapters' current field contract

**Benefit:** make current road impacts findable by the streets and suburbs Council actually names. **Confidence: high. Effort: about 1 day**, with multi-locality matching kept conservative.

Evidence from the [TMR proxy](https://traffic.ipswich.qld.gov.au/dashboard/tmrRoadData): event **835659**, High Street, has `road_summary.locality = "Blackstone"`; [published closure data](https://ipswichfacts.au/data/closures.json) has `suburb: null`, and [Blackstone](https://ipswichfacts.au/suburb/blackstone/) has no impact table. All seven official TMR samples lose locality with the current adapter. From [IMS](https://traffic.ipswich.qld.gov.au/dashboard/imsRoad), **47441** has `road = "Patrick St"`, Flooding, closure impact, advice, nested duration and GeometryCollection; published data retains only its description/suburb among those fields. The [Raceview page](https://ipswichfacts.au/suburb/raceview/) consequently renders a blank Road/Type/Impact row. `Patrick Street` returning 404 alone would not prove ingestion loss; the raw-to-normalised field comparison does.

Scope: `scrape/road_closures.py:_normalise_tmr`, `_normalise_ims`, existing impact/geometry helpers and `build/build_site.py:build_graph` suburb membership. Preserve legacy field variants. Retain a verbatim locality label; for multi-locality strings, match only exact known locality tokens into separate join keys. Reuse existing abbreviation normalisation for `St`/`Rd`. No geocoding, new traffic source, historical snapshots or inferred personal addresses.

Dependencies/constraints: candidate 1's canonical suburb keys; candidate 3's TMR-versus-IMS provenance distinction (QIT Plus rights cannot inherit TMR's licence). Avoid duplicate event merging solely because descriptions sound similar.

Acceptance:

- Absent fields remain absent; legacy fixtures still parse; static pages show the retained fields and correct attribution/source links.

## Documented versus observed behaviour; deferred unknowns

- README says six end-to-end sources and excludes DAs; `CLAUDE.md`/`CONTRIBUTING.md` describe the later metadata-only DA evolution and councillors. Use the detailed **invariant 7** conservatively; the later “do not build a DA scraper” bullet is inconsistent, not authorization to remove or expand that layer. Output excludes named officers, decision/appeal narratives and submission signals. The internal whitelist also retains ID/type/assessment level/coordinates beyond the short prose list; only basic public facts should reach the UI. No privacy expansion is proposed.
- Static-first largely holds: source text is in HTML, search is an enhancement, robots allows crawling, and the sitemap is reachable. But row caps and colliding paths defeat some of the “everything Council has published” wording on street pages. Search defaults to two years with an explicit archive button; that is a deliberate payload policy, not lost history. Current Google indexing was not measured and no Search Console result is claimed.
- Sitemap measured **7,787 entries, 7,763 distinct URLs**. Eleven suburb paths, six street paths and four project paths occur more than once. Only the suburb overwrite has been traced through to demonstrable loss here; street/project duplicates need a separate collision-versus-identical-duplicate audit. Do not change published slugs speculatively.
- Gazetteer comes from observed source suburb labels, not a complete authoritative street/address register. Multi-suburb project labels, misspellings (for example `Wilowbank`), exact-name/stage matches and inferred divisions can miss joins. Candidate 1 intentionally fixes simple equivalence, not fuzzy geography. Low capital-works join rate alone is not evidence that the remainder should match current projects.
- Silent per-source failures remain a code-level concern: traffic catches feed exceptions and can return a fresh empty snapshot, while an empty dashboard is allowed; other parsers skip failed items. Existing floors detect catastrophic count loss but cannot guarantee completeness or a current cache. No source failure was induced and no actual outage is asserted. Also, the traffic scraper's two sequential same-host calls have no explicit inter-request sleep: a later fix should preserve the project's rate limit; this review's fetcher did enforce it.
- Meeting item text truncation, unextracted attachments and using one selected agenda/minutes version are real bounded coverage limits. The two capped items in the sampled agenda illustrate the limit; completeness of omitted content was not audited. Expanding those papers, older capital works layouts or 2019 meetings would require separate source, privacy and parsing work.
- No historical freshness audit of frozen news/minutes, councillor contacts or amended budgets was performed. Current capital works equality is strong evidence for this PDF only. Consultation status differences remain asynchronous observations, not a diagnosed regression.
